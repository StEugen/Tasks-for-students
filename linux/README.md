# Linux laboratories for security foundations

This track follows the basic filesystem exercise in `building-a-boilerplate/`. It moves from combining
commands to writing reusable scripts and investigating Linux as a security operator.

## Recommended order

1. [Pipes and text processing](pipes-and-text-processing/README.md)
2. [Bash scripts lesson](scripts-lesson/README.md)
3. [Permissions, processes, and logs](permissions-processes-logs/README.md)

## Reporting requirement

Submit each laboratory using the shared
[security laboratory report template](../templates/security-lab-report-template.md). Adapt the report
title and terminology to the exercise: assessment report, log-analysis report, script security review,
or incident investigation report. Every important conclusion must reference evidence.

## General rules

- Work as an ordinary user unless a task explicitly requires privilege.
- Read `man` pages and `--help`; do not copy commands you cannot explain.
- Never run destructive commands against paths supplied by untrusted input.
- Keep laboratory artifacts in a dedicated directory under your home directory.
- Submit commands, evidence, and reasoning. Security work without evidence is folklore.
